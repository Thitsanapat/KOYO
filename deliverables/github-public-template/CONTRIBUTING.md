# Contributing

Thank you for helping improve the KOYO beacon decoder evidence package.

## Before Opening a Change

1. Keep changes focused on the public signal-processing flowgraph,
   reproducibility notes, validation summaries, or presentation material.
2. Do not include confidential mission documents, telemetry byte mappings,
   raw signal captures, private correspondence, credentials, local service
   state, or personal filesystem paths.
3. Do not add uplink or telecommand functionality.
4. Preserve SatNOGS data attribution and third-party license notices.
5. Run the public bundle audit and review every staged file before committing.

## Pull Requests

Describe the purpose of the change, the evidence used, and how it was tested.
Mark telemetry interpretations as confirmed, candidate, or not decoded. Do not
present an inferred mapping as confirmed without publication authorization and
reproducible evidence.

By contributing, you confirm that you created the contribution or have the
right to submit it under the license notice carried by the affected file. Files
without an explicit license remain all rights reserved.
